\section{Introduction}
\label{sec:intro}

An LLM agent resends its system prompt, its tool schemas and a growing
conversation history on every turn. Serving stacks therefore reuse cached model
state for almost every request: in a trace of coding-agent sessions, about 96\%
of prompt tokens were served from the prefix cache~\cite{tracelab}, and a
serving-side study reports a 94.2\% hit rate on agentic traces~\cite{vllm-mooncake}.
Studies of agent serving measure what this reuse does for
speed~\cite{tracelab,vllm-mooncake,policy-runtime}.

The reuse is assumed to be invisible to the model's output. It is known not to
be exact: the llama.cpp server documentation warns that with prompt caching the
logits ``are not guaranteed to be bit-for-bit identical for different batch
sizes''~\cite{llamacpp-server}, and recent studies show that cached and
recomputed paths decode different text in half precision~\cite{chodavarapu-fp16,lorup-stage-replay}
and diverge on multi-turn agentic workloads, more so under
quantisation~\cite{patodiya-cache-divergence}. A cache that still holds an
aborted branch can change an agent's action~\cite{zhang-rollback}. What remains
open is when reuse is exact and why, how the difference depends on
architectures beyond dense transformers, whether a cache of exactly the same
tokens changes which action an agent takes, and how to prevent it.

We measure this. In a pre-registered study~\cite{prereg} on one build of
llama.cpp~\cite{llamacpp}, we compare restoring saved state against recomputing
the prompt from scratch, on synthetic agent-shaped traffic with tool calls
against mock tools, for three 4-bit-quantised models whose cached state differs
in kind: a hybrid model with recurrent state, a sliding-window model and a
dense model. Each model runs the same \TurnsPerModel{} agent turns. We find:

\begin{itemize}
\item \textbf{Restore at a natural turn boundary was never bit-exact}:
  \NatInexact{} of \NatTurns{} turns, on all three architectures, while two
  recomputations of the same prompt were bit-identical on every turn.
\item \textbf{It changed the agent's action} on
  \ASparkNatShortAmbPct--\AOrnithNatLongAmbPct\% of ambiguous requests on all
  three models, and on \ExplicitChanges{} of \ExplicitRestores{} restores of
  explicit requests.
\item \textbf{Changes concentrate at near-ties}: \MarginAllNearTiePct\% of
  turns whose top two choices were within 0.5 nats, against
  \MarginAllConfidentPct\% of confident turns.
\item \textbf{The cause we identify is micro-batch tiling}, in an exploratory
  experiment. On the hybrid and dense models, restore was exact when the reuse
  boundary was a multiple of the engine's micro-batch size. Rounding the
  boundary down to such a multiple made every restore bit-exact on those two
  models, at a median cost of \SnapCostMin--\SnapCostMax{} re-evaluated tokens.
\end{itemize}

Several of our expectations failed, and we report them as failures
(\S\ref{sec:limits}). Our design document expected the dense and sliding-window
models to be unaffected; they were not. We pre-registered that the mitigation
would be exact on every model; on the sliding-window model it was inexact at
every 4{,}096-token boundary. All results hold for synthetic traffic, one
engine build, one quantisation, one GPU and greedy decoding.

\paragraph{Contributions.}
(1)~A pre-registered measurement of whether restoring cached state changes an
agent's action, across hybrid recurrent, sliding-window and dense models.
(2)~The behavioural result: action changes on ambiguous requests on all three
architectures, none on explicit requests, concentrated at near-tie decisions.
(3)~A mechanism, micro-batch tiling, and the alignment rule it implies.
(4)~A mitigation, its cost, and the case where it fails.
